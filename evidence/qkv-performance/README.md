# Whole decoder-subgraph latency and allocation review

Both A100 and L4 completed the eight-case matrix at clean workload commit `59210359907c47c73f95304cb17454558daa6f5a`. T4 was excluded. Numerical checks, exact timing-key/sample-count checks, ZIP CRC checks, and retained generated-to-compiled source checks passed.

The workload is residual update + weighted RMSNorm + packed QKV projection. The native lane uses generated native normalization followed by a library matrix multiply; it is not an all-generated projection kernel.

## Whole-subgraph host-visible graph replay

Microseconds below are medians across eight per-case medians. Each case has five randomized rounds of 1000 single-invocation synchronized host samples. Inputs/weights and caller-owned outputs are resident; no input-update copies are included. These are subgraph latencies, not complete token-generation latencies.

| GPU | Eager + library | Native + library | Inductor |
|---|---:|---:|---:|
| NVIDIA A100-SXM4-40GB | 91.573 | 65.685 | 63.641 |
| NVIDIA L4 | 254.559 | 233.652 | 232.709 |

## Projection-only controls and device-batch measurements

Representative batch-1 FP16 cases below show amortized microseconds per invocation inside a 1000-invocation captured batch. Five batch intervals are retained per case/lane. This amortizes host submission gaps; it is not an individually measured kernel or interactive-token latency. Full per-case medians and host p95/p99 values are in A100.json and L4.json. Projection-only paths share the same precomputed, storage-rounded normalization input and persistent QKV output, excluding normalization itself.

| GPU | H | Native whole | Inductor whole | Library projection only | Inductor projection only |
|---|---:|---:|---:|---:|---:|
| NVIDIA A100-SXM4-40GB | 1024 | 12.591 | 12.722 | 8.229 | 10.290 |
| NVIDIA A100-SXM4-40GB | 4096 | 88.519 | 82.183 | 76.296 | 78.479 |
| NVIDIA L4 | 1024 | 28.332 | 29.088 | 25.249 | 26.894 |
| NVIDIA L4 | 4096 | 445.982 | 444.872 | 438.831 | 440.448 |

At H=4096, the library projection-only control takes about 86% of the corresponding native whole-subgraph duration on A100 and 98% on L4 for batch-1 FP16. This indicates projection dominates these wider cases. Separate timing controls are not an exact additive stage breakdown; their medians should not be subtracted to assert intrinsic normalization cost.

Native and Inductor have small-shape crossovers. Inductor is faster for the representative wider cases, while native can be slightly faster on smaller cases. The results establish no general native advantage over Inductor for the tested larger subgraph. The earlier decision to shelve standalone RMSNorm tuning remains appropriate.

## Allocation audit

Three warmed ordinary calls and three single-graph replays were profiled for every lane/case. The analysis checks positive CUDA memory events, peak extra allocated bytes, and recorded CUDA allocation API events.

| Path | Ordinary cases with observed allocation, per GPU | Replay cases with observed allocation, per GPU |
|---|---:|---:|
| Whole eager + library | 0/8 | 0/8 |
| Whole native + library | 0/8 | 0/8 |
| Whole Inductor | 8/8 | 0/8 |
| Projection library | 0/8 | 0/8 |
| Projection Inductor | 8/8 | 0/8 |

Peak extra storage reached 128 KiB for whole Inductor and 96 KiB for projection-only Inductor. Persistent output arguments therefore did not eliminate ordinary internal allocations. Ordinary host measurements remain in the evidence to describe observed runtime behavior, but they are not admitted as allocation-matched native/Inductor speedup claims. Captured replay comparisons reuse captured storage, and all profiled replay calls showed no allocator activity.

## Provenance and cleanup

The matrix is B={1,4}, H={1024,4096}, float16/bfloat16. TF32 and FP16/BF16 reduced-precision reductions were disabled consistently. All three whole-subgraph outputs passed the previously frozen reference gates, with 100 changed-input replays per path/case. Projection-only controls were checked before measurement.

Each GPU retains 400000 host-latency samples and 200 device-batch intervals, each covering 1000 invocations. All raw samples, allocation traces, extension sources/builds, Inductor caches, worker logs, and process status are retained in the export archives. Summaries are generated by scripts/analyze_decode_projection_performance.py.

The initial logs and dispatch remain at L4/dispatch.json; final successful recovery, download and stop are recorded at L4/recovery-1/dispatch.json. Both runtimes stopped, and a separate colab sessions readback confirmed no active sessions.
